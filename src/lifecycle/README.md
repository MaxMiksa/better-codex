# 运行管理

本目录负责启动、安装、体检与恢复策略。程序身份和 Windows 正常退出原语来自 platform，完整依赖预检及恢复决策留在本域。

## 按任务定位

| 目录 | 职责 |
| --- | --- |
| startup/ | 官方普通激活与兼容停止 |
| installation/ | 本机入口、登录启动和源码目录迁移 |
| diagnostics/ | 启动体检、报告、原生窗口和共用控件 |
| recovery/ | 更新发现、预检、取消/防重放和实际恢复执行 |

外部命令保留在 tools/token-hud-local/，仍在使用的参数、返回码及状态路径继续兼容。恢复请求完整启动命令，设置入口通过 `-TaskMode Monitor` 消费 app 回执，不导入其内部函数。

所有路径相对项目根目录；下表是用户操作参考，开发验证不执行真实启停。

新安装默认关闭登录启动及更新监测。登录启动由用户单独启用，应同时关闭 Codex 自身入口，避免无接口实例抢先启动；Windows 启动批准状态由系统管理，不覆盖用户禁用。

管理员启动已移除：完整启动、监测、体检及恢复均不派发提权任务。旧设置 runAsAdministrator 即使为 true 也忽略；迁移旧快捷方式时仅识别本副本原有身份并统一为商店应用身份。

## 启动条件与回执

全新启动前若显示端口被无法核实的监听占用，使用独占回环绑定选择空闲端口，仅通过共享设置锁保存 port，再传入新的本机显示接口参数。不会连接或终止旧监听的拥有者；已运行 Codex 或 `-CheckOnly` 均不改端口。临时绑定释放后仍可能有竞争，实际连接继续要求本机地址、官方包路径与摘要核验。

冷启动统一通过官方商店应用身份激活，保留本机显示接口参数，不直接创建提权程序。已有实例继续复用，不改变其权限；原管理员实例需由用户自然退出后重新打开才能切换。

冷启动在激活前按实际配置等待本机 magpie 接受 TCP 连接，最多 10 秒，为体检原有 30 秒应用发现期限留出时间；未接入 magpie 时不探测、不等待，已就绪时立即继续。配置无法读取、等待超时或 helper 失败均继续普通激活；`MAGPIE_SKIP_WAIT` 保留显式跳过用途。不启动或修复 magpie，不修改模型连接配置。

## 体检与恢复契约

联合入口只在未确认 Codex 已运行时异步打开统一体检；即使 Codex 窗口隐藏，点击快捷方式也不重复触发体检。内部派发、只读检查和后台准备不重复弹窗，手动体检和更新监测仍可触发。检查启动、本地历史、沙箱、VPN/代理及 HTTPS 传输、权限和增强状态，可重查与复制脱敏报告。它不发模型消息、不验证模型鉴权、不控制 VPN；legacy 沙箱不自动初始化账户或 ACL，未知条件保留待确认。

十项检测全部结束、总结果通过且各项为正常或不适用、无需恢复时，体检窗口在 30 秒后自动关闭。异常、需注意、待确认和恢复期间不自动关闭；重新检测取消旧计时，通过后重新起算，普通刷新不延后关闭。计时沿用恢复倒计时的单调时钟与挂起保护，仅关闭体检窗口。

启动检查分别核对进程身份和窗口状态。唯一主进程在等待结束时仍可核对、但窗口隐藏时报告“后台运行”，不把它判成启动失败或宣称窗口响应已通过；窗口缺失/无法枚举为未确认，可见窗口未通过响应探针则单独说明。权限与增强检查继续使用已核实进程，读取前复核 PID/创建时间及程序路径；隐藏窗口本身不产生重开理由。

界面固定为八项：Codex 启动、历史会话、沙箱、VPN 与网络、增强与后台、启动入口、提示词、Codex 更新。内部保留六个原检查与四个管理探针；增强与后台合并依赖/源码版本，启动入口合并实际权限、登录/快捷方式。单行摘要取优先问题，复制报告保留各子项状态和全部说明。十项全部完成或收敛为未确认后才进入恢复判断，新增局部诊断不扩大自动重开资格。

网络检查对连接失败或 VPN 未就绪最多尝试三次，间隔 8 秒；每次重新读取代理配置，并在 HTTPS 探针之后读取 VPN 状态，避免沿用探针前的启动快照。重试期间保持检测中，不阻塞 Codex 启动；证书验证失败与不支持的配置直接返回，不绕过 TLS 或代理。单次代理/HTTPS 超时仍为 2/6 秒；网络底层解析耗时仍受体检窗口既有 48 秒截止兜底。最近一次完成的网络检查保存在 runtime/last-network-check.json，仅含开始时间、各次检查时间、状态、脱敏说明及网关状态，覆盖旧记录，写入失败不影响检查结论。

同一“VPN 与网络”项还核对本机模型网关：仅当所选模型连接指向回环地址且可识别为 magpie 时启用。启动等待与诊断共用 `startup/model_gateway.py`：显式选择的非 openai provider 仅使用自身 `base_url`，不混用内置覆盖或未选 provider；openai 路径依次使用其 provider `base_url`、`openai_base_url`、`chatgpt_base_url`，通过名称、清单或 magpie provider 登记识别接入。不按端口大小决定目标；保留配置的 `127.0.0.1`、`localhost` 或 `::1` 地址，监听身份同时匹配地址与端口。

该项本身不新增界面行，只把网关结论作为第二句并入同一行说明，异常时接管该行状态与建议：端口无响应为异常，端口被非 magpie 进程占用或配置的 magpie 模型清单缺失为需注意，可连接为正常。探测只做短超时 TCP 连接（最多三次、间隔 1 秒）、监听进程名核对与模型清单存在性判断，不读取清单内容、不调用网关接口、不修改配置；监听身份无法读取时不猜测占用，只在可确认属于其他程序时给出需注意。

结果刷新复用现有行控件，原地更新文字、状态与建议，不清空整个列表；仅 DPI 改变时重建带缩放字体的行。标签采用双缓冲绘制，避免文字刷新时先露出背景。

增强模块已加载但尚无适用聊天或文件卡片时，界面及复制报告显示“正常”，说明仍保留等待适用内容；运行环境与后台通过时，合并行的“正常”及圆点统一为绿色。原始不适用状态与恢复判断不变，后台异常或未确认继续保留对应警告或灰色。

体检报告通过临时文件替换发布；Windows 读取占用造成权限错误时，最多重试 5 次、每次间隔 50 毫秒，仍失败则保留上一份完整结果。界面先读取已退出检查进程的最后结果，再区分提前退出（显示退出码）和 48 秒超时；读取失败也不绕过期限，未完成项保持未确认，已完成项不因截止时间被改为失败。

检查进程在 run 执行阶段向外抛出异常时，在本次 output 同目录写入 failure.json，供后续维护定位；导入或参数解析错误发生在该范围之外，不写入此记录。记录只含检查时间、worker PID、异常类型、errno/winerror，以及函数帧的文件 basename、行号和函数名；不保存异常消息、参数、绝对路径或可能含凭据、聊天正文的内容。留存写入失败不替换原异常和退出码，成功检查不创建该文件。窗口清理只删除已知的 result.json/result.next，因此失败记录随本次会话目录保留，界面仍只显示提前退出及退出码。

运行环境检查读取设置与 Codex 配置，执行 Python 依赖和 Node 内置 WebSocket 的最小检测，不启动浏览器或模型；后台身份结合 PID/创建时间、解释器/命令、近期心跳及共用源码摘要。累计写入失败数不单独判定当前故障。坏配置分项说明，不把空配置当有效配置继续检查。

入口检查只读核对项目/任务栏/登录快捷方式目标、AppUserModelID、两个包装器内容、StartupApproved。另读取当前用户已知 Codex 包 App 自启动任务状态：与已确认启用的本项目登录入口并存时提示冲突；关闭为正常，缺失、无权读取或未知状态保留未确认。该探针不写 Windows 登记，不自动禁用原生入口，也不产生重开理由。登录启动未设置属于主动关闭，不新增虚构偏好；其他副本入口不接管，不推断 Explorer 实际固定状态，也不宣称排除所有系统登录或应用恢复机制。提示词探针由 app 可选注入，详细契约见[提示词模块](../prompts/README.md)。

确认增强未加载或刚更新后，全部检测结束才开始按钮内 15 秒倒计时。点击立即执行，X/Esc 取消，Enter 不默认重开；挂起不暗中耗尽倒计时。同次更新/连续故障失败不循环。

手动与自动恢复均先核查执行中的会话；倒计时期间每约 2 秒复查，正常退出前再次核查。发现任务执行中或无法确认空闲时，阻止重开并取消本次自动恢复；之后空闲也不自动恢复倒计时，由用户重新检测、手动操作。更新与已确认增强故障同时发生时，两项已知原因一并取消，不借另一个原因重新触发。

会话核查只读本机 state_5.sqlite 索引和当前桌面实例存续期间的会话任务边界，不输出聊天正文、路径或会话标识。读取上限为 256 条候选、单文件尾部 8 MiB 和约 2 秒扫描预算；缺失、变化、未完整写入或无法判断的记录视为待确认。此为退出前的保守快照，不是对应用内部任务调度的原子锁。

真实体检默认以任务栏最小化状态开始，重复入口复用并刷新同一个窗口，不强制展开。检测结束后，只有异常、需注意、待确认或需要恢复时才自动展开完整窗口，每轮最多一次。全通过时保持最小化；若此前因问题自动展开，复查通过时收回任务栏，再按上述规则关闭。未自动展开、仅由用户从任务栏打开的窗口不强制收回。展开后仍置顶，但不主动抢占输入焦点；开发预览仍直接显示完整窗口。无需恢复时，启动按钮与重新检测采用相同中性外观；需要恢复且允许操作时才突出显示。按钮按当前文字适配宽度，仅倒计时阶段预留两位秒数，避免每秒抖动。

执行前复核包、摘要、PID/创建时间与依赖，仅用 Windows Restart Manager 对以 PID/创建时间登记的唯一实例请求正常退出，拒绝退出则保留应用。使用无强制标志的普通关闭，不要求 Codex 自身登记系统自动重启；`RmShutdownOnlyRegistered` 表示后者，并非只关闭本次登记的资源。无法核实的旧端口不单独阻止该动作，由完整冷启动入口避让；连接成功仍须验证新监听身份，完成检查重新读取持久端口。体检窗与恢复执行独立于增强后台：已开始正常退出的执行器完成一次完整增强启动，不因窗口或后台关闭停在 Codex 已退出的中间状态。

确认当前唯一主进程未请求显示接口时，体检报告明确的缺接口警告，即使旧端口仍有残留监听。旧快照或未核实的实例不能单独触发这个结论。

## 更新、停止与入口状态

更新监测约每 15 秒读取注册版本，首次只建基线；升级且新版唯一主进程稳定运行至少 15 秒后转交同一体检。启用时先建立当前基线，不以启用动作授权重开已工作的旧实例。关闭监测不会取消已打开的倒计时，须在窗口 X 取消。

Codex 更新在同一体检中显示后台监测开关、运行状态、转交及最终取消/防重放事实。运行新鲜度取已核实 supervisor 的心跳；update-recovery.json.checkedAt 只是状态变更时间，长期未变化的 baseline 不视为故障。Set-UpdateRecovery 开关、现用观察器、动态桥及持久状态仍服务这条唯一链路，旧独立窗口已退役，不存在第二个自动恢复引擎。

Stop 请求停止自有后台和子进程，不等于永久禁用。结合 supervisor 状态 stopped 与进程退出判断完成；下次联合入口可恢复。launch-receipt、后台状态与实际页面分别核对，不用旧回执推断当前正常。

快捷方式文件存在不代表系统已固定。完整入口和源码改名的维护流程在本机 launchers/README.md；安装身份、未知字段及持久取消记录均须保留。

## 验证

`runtime_events.py` 把现有更新、体检和恢复结果映射为脱敏事件；不增加探针或恢复引擎。完整体检保存十个底层项（对应八行界面）的状态与已知说明代码，超时、提前退出和取消保留未完成原因。原始说明和动态值不入库；未知说明保留 evidenceUnavailable。`observability` case 覆盖存储与映射，现用后台和自然升级另行验收。

从项目根运行 scripts/check.py 的 `diagnostics`、`diagnostic-worker`、`management`、`relaunch`、`session-activity`、`updates`、`supervisor`、`launcher-5`、`launcher-7`、`native-close`、`native-exit`、`native-countdown`、`native-recovery-guard` 或 `relocation`。使用假进程、假网络、隔离入口或显式 Preview；native-exit 仅正常退出测试自建窗口进程，不重启/停止现用 Codex 或 HUD。真实升级恢复与全部桌面条件仍需独立验收。
