# 界面增强

本目录负责已核实本机显示连接上的每窗增强；运行管理不在此决定，提示词监测也不由界面托管。

## 模块与入口

| 目录 | 职责 |
| --- | --- |
| host/ | CDP 连接上的 Node 控制器、窗口任务、状态写入和采集会话 |
| statistics/ | HUD、聊天绑定、格式化、本机 magpie 统计读取及 collector/ 本地采集器 |
| reading/ | 正文/表格阅读增强、临时列排序与宽度设置命令 |
| file_changes/ | 多文件列表默认收起及展开状态 |
| appearance/ | Custom 配色、可读前景、原生命令菜单显隐与 AI 重命名状态 |

采集器源自 codex-token-hud v1.3.0-beta.8，版本和 MIT 许可见 [VERSION](statistics/collector/VERSION) / [LICENSE](statistics/collector/LICENSE)；稳定旧 collector 命令和许可位置继续保留。

## 数据来源与关联

本地采集器仍负责会话发现、当前轮次、canonical `token_usage_record` 与 `response_id`。每个窗口选择聊天后先尝试读取本机 magpie 统计接口；只有本地已存在当前 canonical 响应时才能关联。因此这是 magpie 优先、本地会话采集兜底，不是完全停止读取 Codex 会话记录。

- magpie 设置从 `$XDG_CONFIG_HOME/magpie/settings.json` 读取，未设置 `XDG_CONFIG_HOME` 时使用 `~/.config/magpie/settings.json`。只请求 `http://127.0.0.1:<port>/v1/magpie/usage/requests`，固定携带 `agent=codex`、`via=through`、`period=all`、`q=<thread id>` 与 `limit=20`；端口缺失时沿用接口默认值 3425。
- 关联必须同时满足本地确定聊天 ID 与 `native_session`（缺失时使用 `session`）一致，以及本地最近 canonical `token_usage_record` 的 `response_id` 与网关记录一致。只接受成功完成的实际网关请求，排除带 `source`、`computer`/`via`、后台 `kind`、子代理或父代理标记的记录，以及失败、拒绝和中转尝试；不按 provider/model 名称筛选，Kimi、DeepSeek 与 Codex 路由均适用。新增 TTFT/TPS 显示不改变这些关联、过滤和整份回退规则。
- 同一聊天普通轮询最多每 2 秒读取一次；连续 3 次连接或传输失败才把 magpie 标记为不可用。确认离线后退避为每 30 秒探测一次，成功即恢复。HTTP 错误和坏格式不判定连接离线；单个 route 速度请求失败后 2 秒内不重试。切换聊天或强制刷新仍可立即读取。单次超时 0.75 秒，响应最多 2 MiB；不读取凭据，不使用代理，不跟随重定向，不发送模型消息，也不修改模型连接配置。
- 缺精确匹配、时序未知或过期、字段不完整、响应身份重复或接口不可用时，保留整份现有本地样本；magpie 与本地样本不混用计时或用量。当前 magpie 轮次可保留已确认的有效速度；本地模式只使用本地请求边界均速，不因瞬时缺值在同一轮切换来源。本地样本仍提供缓存和统计时间；若本轮已有缓存的首次 TTFT，仍可显示 `metrics.turn_ttft_ms`，否则显示 `-s`。模型标签仍取本地记录，不展示返回模型。

## 统计口径与关联

- HUD 默认按“TTFT 值 → TPS 值 → 缓存比例 → 相对时间”展示，可在界面设置中调整顺序和显隐，不显示 `TTFT`/`TPS` 字样；示例为 `11.24s · 45 tok/s · 98% · 31s`。TTFT 显示到两位小数的秒数，TPS 与缓存取整；缺失项分别显示 `-s`、`- tok/s`、`-%`，不展示返回模型。TTFT 悬停说明本轮首次响应耗时；速度悬停说明随来源切换，分别解释本轮 magpie 有效值或本地兜底请求均速。
- magpie 的 `out` 已包含计入的推理 token，输出量直接使用 `out`，不再叠加 `reasoning`；总输入为 `in + cache_read + cache_write`。统计时间取 `t + ms`，`cache_unknown` 表示缓存信息未知，显示 `-`。
- TTFT 使用 `metrics.turn_ttft_ms`，只锁定本轮已见起点后的首个 canonical 模型响应；首个 canonical 记录没有 `response_id` 时保持缺失，不以后续 ID 冒充首次。本轮后续请求、API 失败和本地兜底不替换它，新轮无首样本时清空，缺证据显示 `-s`。`last.ttft_ms` 只属于最近响应，不作为界面 TTFT。单次响应 TTFT 取 magpie `ttft_ms`，要求 `0 < ttft_ms <= ms`；缓存和相对时间取最近响应。

### 速度来源与回退

- 速度来源按聊天和轮次起点固定，每窗最多缓存 8 个速度 scope；新轮删除该聊天旧 scope 并清空旧速度。未确认离线的轮次使用 magpie，已确认离线后的新轮次使用本地兜底。
- magpie 模式使用本轮最近一次有效的正速度：按当前 `route_id` 再读同一接口，结果必须恰有一条与 `route_id`、`response_id` 和聊天 ID 精确关联的记录，`calls`/`decode_n` 严格为整数 `1`，且 `decode_out`/`decode_ms` 有效；速度换算为 `1000 * decode_out / decode_ms`，写入 `metrics.turn_speed`，`rate_basis=magpie-native-speed-v1`。每个窗口最多缓存 16 个 route 速度；最新请求缺速度或 API 失败时保留上一次有效值，新轮清空，同轮不混入本地均速。
- 确认 magpie 不可连接后，从新轮起 `speed_mode=local`，使用最近 canonical 响应的请求边界均速：输出 token 数除以已知请求边界至响应用量记录的耗时，包含等待和推理，排除已知工具执行；输出量沿用 canonical 记录，包含推理和工具调用 token。要求请求边界和输出量完整、耗时至少 50ms。结果写入 `metrics.turn_speed`，`rate_basis=response-request-average-v2`。同一轮即使 magpie 恢复也不切换，恢复后的下一轮再使用 magpie；边界不足显示 `- tok/s`。
- 不用经验速度上限修饰或掩盖计时错误；边界不足时保留缺失状态，先核对来源与请求边界。
- 正常 monitor 使用 `TailCache(calculate_speed=False)`，继续解析用量、缓存、时序和 canonical 关联，但暂停逐日志本地测速；只有 `local` 模式才按已有请求边界计算均速。前端按 `speed_mode` 选择来源，并校验 `source`/`rate_basis`、聊天、轮次起点和模型，防止两套速度混入。
- magpie 通常读取最近 20 条；首次 TTFT scope 尚未找到 first response ID 时可一次性扩展至 500 条，每窗最多缓存 8 个首次 TTFT scope。首次 scope 允许首记录早于 15 分钟，只要 thread、turn、起点和 first response 精确匹配；最近响应仍按 15 分钟过期。API 失败或本地回退时，已有 scope 缓存仍可提供 `turn_ttft_ms`。
- 缓存比例沿用来源口径：本地为 `cached_input_tokens / input_tokens`，magpie 为 `cache_read / (in + cache_read + cache_write)`。有效统计的相对时间在所有界面语言中统一使用不带前后缀的英文单位（`0s`、`10s`、`2min`）。最近响应满 15 分钟时，magpie 模式保留本轮已知 TTFT 和有效速度，缓存与相对时间过期；本地速度不跨过期保留。绑定失败、采集心跳失效、轮次或模型不匹配仍按原规则隐藏或清空。
- 优先主输入区的正式聊天 ID。临时 ID 仅在标题与本地索引唯一精确匹配时回退；不借用其他窗口或子代理数据。新轮次、错误绑定和旧 generation 不沿用结果。

## 页面与偏好

点击 HUD 打开界面设置。正文宽度最高 1600px；滑杆步长 16px，数字输入接受 768–1600 内任意整数，只在回车或点击面板外时提交，超出范围的值恢复为当前有效宽度；文件变更列表可设置默认展开或收起，同卡片的手动状态优先；Custom 配色可关闭。“表格优化”与“diff 界面优化”同级，右侧总开关控制全部表格增强，折叠箭头位于标题与开关之间；展开后提供“表格整体居中”开关与“排序”分段选择器，后者三选一为智能、默认升序、默认降序。关闭总开关会移除列宽、居中和排序增强并停用两个子项，重新开启时沿用已保存的子项选择。统计四项按当前统计条顺序排成一行 Toggle Group，宽度随文字长度按比例分配，整个按钮可直接拖动排序；点击切换显隐，拖动交换位置后立即热更新统计条并自动保存，至少保留一项。顶部按“已保存状态、撤销、重做、恢复默认”排列；恢复默认只在右上角出现，底部不重复。设置面板宽度 360px，宽度、文件、配色、表格、统计和工具栏共用同一网格；使用标题、正文和紧凑三级字号、较轻字重，分割线与边框统一为 2px。暗色表面下，开关圆点和激活按钮文字使用黑色；浅色表面使用白色。字号随原生输入区控件。主/侧聊天和子代理受各自面板宽度约束，输入框不变。Chat 模式也沿用阅读宽度与回复字号，文档与空白页保持原生。

「AI 回复字号」在正文宽度下方，接受 10–40 px 整数，回车或移开焦点后立即生效并自动保存。留空或恢复默认时跟随 Codex 原生字号；无效输入保留上次有效值。只调整聊天里的助手回复，保留其原生排版比例；不改用户消息、输入框、侧栏、原生设置或窗口缩放。既有和新挂载的回复均生效，支持撤销/重做和多窗口同步，关闭增强后还原。

助手回复中的原生 Markdown 表格独立于正文宽度，保留原生字体、对齐、操作和滚动结构。列宽按内容实际排版尺寸分配，覆盖原生按字符数分档的宽度限制；数据内容不换行时均不超过 6em 的短列留出 20px 列间距，长文字列保留 32px，最后一列数据格的原生尾部留白不变。原生工具区移至表头上方时，最后一列表头尾部留白与数据格一致。间距按实际文字几何尺寸判断，不猜测列名或数值类型；内容增长或缩短时重新判断。短列自然收窄，长文字列保留 `min(不换行时的自然内容宽度, 6em)` 的可读下限；各列内容宽度上限默认 28em，按减少整行换行的收益可扩展至 40em；单表共用 12em 的额外宽度预算，下限和上限均不含单元格内边距与边框。空间不足时优先在表格内部横向滚动，避免把多个长文字列挤成竖条。合并单元格不增加测量下限，继续由浏览器按合并结构排版。

额外宽度根据不换行时的文字几何尺寸分配，不复制或读取文字字符串。以各行最高的估计行数衡量收益，同时扩大互相制约的长列；每次选择单位额外宽度收益更高的方案，至少减少相当于数据行数 20% 的估计行数才采用。单元格估计行数最多计四行，避免个别极长内容主导整张表。显式换行和段落按自然横向范围测量；最终换行仍由浏览器决定，不保证估计行数与实际行数完全相同。短列、数字列和无明显换行收益的表格保留原有宽度，内容缩短后释放扩展。

取消表格及包装层至少撑满正文的限制；“表格整体居中”开启时，整体相对所在正文块居中，不叠加原生宽表的网格居中偏移，超出正文的部分左右对称，正文追上或超过表格时也不强制对齐。容器最多占用该面板围绕正文中心的对称可见空间，并受 `min(80 × 表格字号, 1440px)` 的整表舒适宽度上限约束；16px 表格字号时上限为 1280px。整表仍按内容收窄，不随更宽的显示器无限拉伸；超过可读下限后仅在表内滚动。关闭居中时保留智能列宽和可读性增强，仅恢复原生起始对齐。正文使用默认宽度时同样生效；分栏改变自动重算边界，新表格挂载即时应用。自然宽度只在首次挂载、表格内容或样式变化、字体参数变化时重新测量，普通轮询复用几何缓存；测量标记在同一次执行中移除，不读取或保存聊天正文。仅处理已识别结构的助手表格，不改用户消息、打印副本或文档；停止增强还原原生布局并移除测量样式。

普通助手 Markdown 表格可点击表头，按“首选方向 → 相反方向 → 原始顺序”循环。首次点击方向由设置中的智能、默认升序或默认降序决定。智能模式默认降序；原始顺序连续递增或递减的至少三个纯整数，以及相同字母前缀加整数的编号列默认升序，前缀编号可以从 P2/T2 等任意编号开始或缺号。显式升序/降序覆盖编号自动判断；不根据“成本”“优先级”等列名猜测方向。未点击时保留原序。

按住 Ctrl 依次点选列，先点的优先级最高；每次重新按下 Ctrl 后，首次点选开始新组合并覆盖此前组合，松开后保留结果。同一区段重复点同列忽略。Alt 点击未选列只预设该列方向，不改当前组合；点击已选列立即反向并保持优先级。方向预设在当前表格挂载期间保留；普通点击其他列回到单列排序。

表头使用内置 Lucide arrow-down-narrow-wide 与 arrow-down-wide-narrow SVG：短横条在上表示小值在上，长横条在上表示大值在上；激活的列更醒目，多列组合另显示 1、2、3 等优先级。逐列同步比较带控件与不带控件的自然宽度；正文已有足够宽度时，控件继续紧跟标题并常显。只有控件确实增加列宽时才脱离排版、利用表头尾部留白：未选择列在悬停或键盘聚焦时显示，已排序或 Alt 预设的列常显，组合排序的优先级显示在图标下方，不额外占横向宽度。悬停与聚焦不改变列宽，不主动拆分或缩写表头，不新增设置项。测量按内容、字体及表头间距变化失效，并覆盖阅读增强的列宽下限后比较真正的自然宽度；普通滚动与尺寸轮询复用缓存。复制和展开按钮由 Codex 原生定位在表头同一行的最右侧，沿用原生显隐规则、点击行为及末列标题留白。窄表可由原生按钮占用一部分末列标题空间。不加载图标库或外部资源。支持 Enter/Space 操作，悬停提示跟随页面中英文。

中文及普通文本使用页面语言的自然文字顺序；整列均为数值或同单位数值时按数值比较，支持千位分隔、负数、货币和百分比。同值再比较下一优先级，最后保留原始先后；空值、破折号与 N/A 始终置后。不同币种或单位不猜测换算，使用文字排序。单元格 emoji/图标作为完整原内容的一部分参与普通文字比较，不增加颜色优先级或忽略后续文字的专用规则。比较值与排序结果仅在页面内存缓存，内容变化时失效，普通尺寸变化复用比较结果。

排序由独立的 table-sort.js 托管，仅在当前页面内存比较单元格值，再平移原始行的视觉位置。不会改动原始行节点顺序、行文字、消息状态、Markdown、磁盘记录或模型请求，也不会发送聊天消息；原生复制及辅助阅读仍沿用源顺序。流式追加、行高和窗口宽度变化后更新视觉排序；表头被原生渲染器重绘时恢复入口并回到原序。表格卸载、隐藏、页面重载或停止增强后清理临时状态。仅处理至少两行数据、单行表头、无合并单元格的规则表格；用户消息、打印、文档及已有独立行平移的表格保留原样。容器识别同时保留语义属性和直接父子结构检查，只匹配 TableScroller/TableWrapper 角色名，不依赖类名哈希的下划线或连字符形式；列宽和排序使用相同兼容范围。居中和排序偏好各自保存，局部失败不撤销其他增强。图标许可见[第三方说明](../../THIRD_PARTY_NOTICES.md)。

文件预览不属于上述表格支持范围。已检查的 Codex `26.1103.4239.0` 将 Markdown 表格显示为可编辑的 CodeMirror 行及单元格装饰，并按滚动虚拟挂载；扩大原生聊天表格选择器不能完成适配，不能把已挂载行视为完整表格。

统计栏优先在输入区底栏居中；避让范围包含按钮、下拉框，以及额度圆环等可选控件的可见文字、图形和装饰，不依赖控件名称或类名。按实际内容占位计算，不把铺满底栏的布局容器当成障碍；跳过编辑区。动态添加、隐藏和尺寸变化后重新计算，在保留水平 12px、垂直 4px 安全间距的可用空隙内按像素移到离中心最近的位置。完整四项在左右空间内均放不下时，只显示当前顺序中前两项已启用统计（默认 TTFT 和 TPS）；空间恢复后自动恢复其余项。隐藏的字段继续接收当前统计。仅几何位置受限不清空聊天绑定、generation 或统计，避免数值变长后隐藏、清空变短后再出现的循环；模型名称跨过中线时仍可作为字体参考。

问题卡片、完整视图浮动输入区出现时隐藏 HUD 并关闭设置面板，退出恢复；无唯一主输入区、未知布局或连 TTFT/TPS 都无法安全放下时也隐藏。多文件默认 0 行，可展开全部/再次收起；同卡片的手动展开保留，新卡片默认收起。单文件标题和查看变更/撤销入口保持原生，停止增强恢复列表。

Custom 配色仅修正自定义色下的消息气泡和输入框按钮，选择可读黑白前景，预设色保持原生。标签跟随 Codex 页面语言，未声明时才回退启动语言；支持英文/简体中文，其他语言回退英文。

## 命令菜单

横排命令按钮从首帧起预留固定的 16px 图标位。原生 SVG 延迟挂载、移除或内容变化时，仅替换图标位的内容，不改变按钮宽度、文字位置或重建整排。原生源项及纯命令分区采用不可见、不可交互的绝对定位，保留视口交叉几何，避免原生虚拟化将图标替换为纯文字占位；不占额外菜单空间，关闭增强时恢复原状。

界面设置的「命令界面优化」默认收起，展开后可独立展开「命令」或「Skills」。拖动子项标题旁的把手或聚焦把手按上下键可交换两项，`commandSectionOrder` 只保存设置页顺序，不改变 `/` 菜单。命令内部保留成组按钮和排序把手，不显示组标题。外层右侧提供 `commandMenuEnabled` 总开关，默认开启，收起时也能使用。关闭即时移除分组展示及过滤，释放方向键并完整恢复原生菜单；开启即时恢复已保存的分组、项目及顺序。保留子项设置，支持自动保存、撤销/重做及多窗口热同步，不重启 Codex。设置操作每次获取当前命令模块，独立重新加载后不会继续使用已撤掉的旧实例。

`appearance/command-menu.js` 仅增强已识别的原生顶层斜杠菜单。默认八项按聊天管理、上下文与分流、项目工作横排成三行；每行取已开启且原生当前提供的命令，数量实时变化，空组隐藏，不补造不可用入口。其他命令分为聊天整理、模型与推理、工作模式、工具与连接、创作与伙伴、状态与帮助；发现的未知命令进入待分类，默认隐藏。共享命令目录同时生成设置中的多选分段按钮组及菜单布局，避免两份分组定义。

命令区下方依次为 `Skills` 和 `Prompt`，各自有居中的非交互标题及左右细线，空区连同标题隐藏。两区共用三列纯名称按钮，不显示图标、说明和来源；长名称省略，悬停显示全名。按不区分大小写的数字自然顺序排序，每列容量为条目数除以三后向上取整，从上往下填满左列，再填中列、右列，例如 10 个为 4＋4＋2。两区均不参与命令多选和排序。

斜杠菜单高度随内容变化，不预留空白行。原生菜单使用输入框锚点的可用高度，独立菜单使用输入框上方实际可用的空间；仅在内容放不下时滚动。菜单宽度、三列布局及其他触发器不变。

Skills 优先使用原生 `/` 菜单的结果和点击操作。新版 Codex 把本地技能放到独立的 `$` 选择器时，`/` 使用当前输入框对应的原生本地技能查询，按名称过滤。首次打开且查询尚无结果时，按需启动 Codex 已注册的同范围查询；返回后只刷新仍打开的菜单；不扫描目录、不借用其他项目的技能。选择后用原生编辑器把当前 `/查询` 替换为技能引用，只编辑草稿，不发送。无法确认技能来源或编辑位置时不补造入口。

在「界面设置 → 命令界面优化 → Skills」里可逐项显隐。默认隐藏 Health、Excel Live Control、Spreadsheets、Visualize 和 Create Statusline，其他技能默认显示。设置随界面偏好保存，支持撤销、重做、恢复默认和多窗口同步。隐藏只作用于增强后的 `/` 菜单（包括搜索和键盘选择），不禁用技能、不修改 Codex 技能设置，也不改变原生 `$` 选择器。

Prompt 读取 Codex Home 的 `prompts` 一级目录，只显示可用的 UTF-8 Markdown（`.md`）文件名，不含扩展名。跳过隐藏项、链接、不可读、空白、非 UTF-8 和超过 256 KiB 的文件；不扫描子目录。只在打开菜单时检查文件变动，未变文件复用内存缓存，不定时扫描。命令、Skills 和 Prompt 同一帧显示；读取超时则用上次成功读取的结果（没有则先显示其他内容）。已有缓存时保持本次布局；首次无缓存时，迟到的结果只补入仍打开的同一次菜单。激活后去掉文件开头带完整分隔符的 YAML frontmatter，将剩余 Markdown 原文插入当前草稿光标处；仅在必要时补换行，不替换草稿、不展开占位符、不发送。插入使用正常编辑事件，按原生路径关闭菜单，焦点保留在编辑器。仅在激活 Prompt 时检查当前编辑器的选区及相邻文本；不直接修改 React 状态，增强也不将 Prompt 正文另存到状态、日志或其他文件。

新对话没有原生 `/` 菜单时，当前编辑器行尾的 `/查询` 会打开输入框上方的独立菜单，按同一规则显示已加载的本地 Skills 和 Prompt；等待原生技能查询时可先显示匹配的 Prompt，两个区均无结果则不显示。独立菜单复用三列名称、自然排序、方向键/回车、查询过滤和插入规则；原生菜单出现、输入离开 `/查询` 或关闭总开关时立即移除。

`commandVisible` 是同一偏好文件中的 ID → 布尔值映射，保留未知字段和命令选择。`commandGroupOrder` 保存组序，`commandItemOrder` 保存组内顺序，旧版其他组的命令顺序按归属拆分迁移。设置中通过拖柄移动整组，直接拖动命令按钮排序，也支持聚焦后按上下键；左右键仅在组内移动焦点。沿用自动保存、撤销/重做和恢复默认，窗口间实时同步。

设置中的开启代表允许显示，不覆盖原生可用条件。例如“初始化”在当前聊天执行任务或目标模式中暂不提供；任务结束且其他条件满足后恢复，设置开关不会因此关闭。

菜单在独立展示区域创建横排按钮；原生行保留原位置并临时隐藏。仅在已确认的顶层 `/` 菜单中接管方向键、Home/End、回车和 Tab：左右同行循环，普通上下逐行移动，Ctrl+↑/↓ 按命令组、Skills、Prompt 跳转，首尾循环。上下移动保留期望列，尽量选择最接近该列的条目，标题不参与导航。空结果阻止提交隐藏项；输入法组合、其他修饰键、设置区域、子菜单和原生 `@`、`$` 提及保持原行为。原生结构或元数据无法完整识别时还原整个菜单；关闭总开关或停止增强删除展示区域、还原原生菜单和键盘。

## 自动隐藏输入框

在「界面设置 → 自动隐藏输入框」选择「关闭」（默认）、「最小化」或「完全隐藏」。只有已显示消息的主聊天才允许收起；空白新聊天、草稿、附件和原生待操作状态保持显示。启用后，空闲的空输入框离开焦点才收起。最小化可点击「展开输入框」，两种收起方式都支持快速连按两次 Enter 展开并聚焦。展开不会提交内容；需要改设置时先展开，再点原来的统计条。切换时保留原生编辑器，未识别的布局保持原样。

## AI 重命名

左侧聊天列表的右键或「…」菜单顶部提供带闪光图标的「AI 重命名」；斜杠菜单仍可对当前聊天使用。点击一次就锁定目标聊天的 ID，后台完成生成、保存和核对；切换聊天不会改变目标。斜杠菜单只清除触发用的 `/`，不改写已有草稿，两个入口都不发送聊天消息。

- 只读取 Codex 当前为该聊天登记的会话文件，并核对文件中的聊天 ID；不使用可能仍指向旧记录的历史索引，也不拼接同 ID 的其他文件。读取期间路径或文件发生变化时重试一次；仍不稳定、无法读取或没有用户消息时保留原标题并说明原因。正文只取用户消息和助手 `final_answer`，不读 commentary、reasoning 或工具输出；注入的 AGENTS.md 与 environment context 不计入，图片记为 `[图片]`。
- 发给 Luna 的聊天正文使用 `【第 1 轮】`、`【用户消息 1】` 和 `【模型回复 1】`，正文另起一行，两个角色在每轮内各自重新编号。用户消息不截短；每条助手最终回复按中英文句子边界只保留第一句话。沿用本地轮次与消息顺序；没有轮次标记时，把助手回复后出现的用户消息视为下一轮。没有最终回复的轮次不补造回复。
- 通过本机官方 Codex CLI 的 `exec --ephemeral -m gpt-6-luna -s read-only` 生成标题，沿用同一 Codex Home。仅这次命名调用使用 Luna 支持的最低推理档 `low`，直接返回标题 JSON，不修改日常聊天的模型设置。提示词只经 stdin 传入，不落临时提示词文件；聊天正文不写状态、日志或运行历史，只保留结果、模型及保存耗时、标题长度等元数据。
- 标题统一为 `类型：描述`，使用中文冒号，前后不加空格。模型返回半角冒号时，保存前也会转换成这个格式。类型使用 `feat`、`bug`、`ui`、`docs`、`refactor`、`chore`；修复类统一为 `bug`。描述始终中文，专有词可保留英文，总长度不超过 24 个 Unicode 字符。
- 从整个会话判断用户的多轮工作围绕哪些核心关键词或对象展开，默认选一个，通常不超过两个。描述可直接使用核心关键词或对象名称；需要说明具体动作时，也可加动词组成简洁短语。
- 每次只请求一次 Luna，不分段、不生成摘要。会话过长导致请求失败，或模型输出不符合标题规则时，保留原标题。
- 保存只通过 Codex App Server 的 `thread/name/set`，随后用 `thread/read` 复核同一 ID 和标题。优先使用桌面当前的本地 App Server，让原生界面接收标题更新；如果写入前无法使用该连接，才用独立的短时本地 App Server，侧栏可能要等原生刷新才显示新标题。不操作重命名弹窗，不直接改数据库；同一个聊天同时只运行一个重命名。如果写入后无法核实结果，提示未确认，不重复提交。
- 仅适用于有本地会话记录的聊天，需要官方 Codex CLI 可找到且 Luna 可用。点击后整理出的用户消息与最终回复首句会经本机 Codex CLI 发送给模型，这是本功能唯一的聊天内容外发路径；不同意时可继续使用原生“重命名”。

## 故障隔离与持久状态

`runtime_events.py` 由 supervisor 消费现有连接回执与带 controllerPid 的新鲜页面快照，仅记录连接、增强加载/等待/失效的状态变化；不读聊天元数据，不新增浏览器探测，不由 Node 打开 SQLite。记录失败不撤销增强。通用存储见[运行历史](../platform/observability/README.md)。

每个窗口拥有自己的 selection/metrics、采集器及清理。页面退出或连接结束才移除整窗增强；采集器退出只使本窗口统计不可用，按退避和滚动一分钟最多三次启动预算恢复，保留原 HUD、宽度、文件列表与配色。接收新数据须匹配当前采集 PID、启动后的心跳及聊天/generation。

宽度、AI 回复字号、配色、文件列表默认状态、表格居中与排序方向、统计顺序和显隐偏好由 platform/settings/ 在同一锁内合并；读取失败保持最后有效值。撤销/重做历史只属于当前页面会话。单张文件卡片的展开状态和统计属于各自窗口，偏好可以安全共享。

开发中局部替换界面模块时，若本轮新增或迁移了语言键，必须同时移除页面内的 `__codexHudI18n` 及依赖它的 HUD、表格模块，让现有 controller 按“语言包 → HUD → 表格增强”重新注入；只替换业务模块会保留旧语言包并显示原始键名，但不影响本地表格功能状态。
